# المرحلة 0 — نطاق النسخة التجريبية لنظام الاختبارات

## الحالة
معتمد للتنفيذ — النسخة 1.1

## الهدف
إثبات أن المشروع يستطيع تحويل **بنية امتحانية موثقة** إلى تجربة اختبار مفيدة للطالب، لا مجرد رابط PDF، مع الحفاظ على بساطة الموقع وسرعته وعدم الحاجة إلى حساب أو Backend.

## النطاق المعتمد
- المادة: الرياضيات فقط.
- الفرع: التفاضل والتكامل فقط.
- المحتوى: محاكاة واحدة في الإطلاق الأول.
- المرجع: نموذج/حزمة تعليمية موثقة لبنية الاختبار، مع توثيق المصدر والسنة.
- يسمح بأن تكون أسئلة المحاكاة **متكيفة `adapted`** وليست نقلًا حرفيًا، بشرط التصريح بذلك في البيانات والواجهة وعدم وصفها بأنها أسئلة وزارية حرفية.
- إذا كان السؤال منقولًا حرفيًا `verbatim` فيلزم تتبع صفحة المصدر ومفتاحه المنشور.
- إذا كان السؤال متكيفًا فيلزم تحقق رياضي مستقل للإجابة وسجل قابل للمراجعة.

## تجربة الطالب
`فتح المحاكاة → اختيار موقّت/غير موقّت → الإجابة سؤالًا سؤالًا → حفظ واستكمال → تسليم → نتيجة → مراجعة الأخطاء`

## ما يبقى خارج النسخة التجريبية
- مواد أخرى أو أكثر من نموذج في الإطلاق الأول.
- حسابات ومزامنة سحابية.
- Backend أو قاعدة بيانات.
- AI داخل التصحيح.
- نشر OCR آليًا دون مراجعة.
- تشخيص تكيفي طويل المدى أو ترتيب الطلاب.

## مبادئ الجودة
1. الدقة قبل الكمية.
2. provenance صريح: `verbatim` أو `adapted`.
3. لا ينشر سؤال قبل `verified`.
4. لا تشخيص قاطع من سؤال واحد.
5. لا تفسير لبديل خاطئ دون مبرر تربوي.
6. الهاتف أولًا.
7. حفظ المحاولة محليًا وعدم فقدانها عند الإغلاق.
8. وضع المحاكاة لا يكشف الصواب أثناء الحل.

## تعريف النجاح
تنجح النسخة إذا استطاع طالب إكمال الرحلة كاملة، وإذا كان محرك التصحيح **مطابقًا 100% لمفاتيح الأسئلة المعتمدة داخل بيانات المحاكاة**، وكانت تلك المفاتيح مرتبطة بدليل مناسب لطبيعة السؤال: مفتاح منشور، حل منشور، أو تحقق مستقل موثق.
