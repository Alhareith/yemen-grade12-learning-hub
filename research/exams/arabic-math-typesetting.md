# تنسيق الرياضيات العربية في المحاكاة

## الهدف
عرض أسئلة الرياضيات داخل محاكاة الثالث الثانوي بصياغة بصرية قريبة من الكتاب والاختبار العربي، من دون تغيير بيانات السؤال أو مفتاح الإجابة أو منطق التصحيح.

## القرار التقني
اعتماد **MathML الأصلي في المتصفح** مع `dir="rtl"` لكل صيغة رياضية، بدل عرض النص الرياضي الخام أو الاعتماد على صورة للسؤال.

الأسباب:
- MathML يمثل الكسر والجذر والأس والحد والتكامل كبنية رياضية فعلية، وليس كسلسلة نصية.
- اتجاه الصيغة الرياضية يضبط مستقلًا عن اتجاه الفقرة العربية، وهو ضروري لتفادي قلب الأقواس والعلاقات بطريقة خاطئة.
- المتصفحات الحديثة تدعم MathML واتجاهه دون مكتبة تشغيل أو CDN إضافي، وهذا يناسب شرط السرعة وضعف الاتصال.
- البيانات الأصلية تبقى ثابتة؛ العربنة تحدث في طبقة العرض فقط، لذلك لا تتغير الإجابات أو الاختبارات الآلية.

## الاصطلاحات المعروضة للطالب
طبقة العرض تحول الرموز الشائعة إلى الاصطلاح العربي المستخدم في كتب ونماذج الرياضيات العربية واليمنية:

| المصدر الداخلي | العرض العربي |
|---|---|
| `x` | س |
| `y` | ص |
| `f(x)` | د(س) |
| `d/dx` | د/دس |
| `sin` | جا |
| `cos` | جتا |
| `tan` | ظا |
| `cot` | ظتا |
| `sec` | قا |
| `csc` | قتا |
| `ln`, `log` | لو |
| `e` | هـ |
| `C` ثابت التكامل | ث |
| `u` في التعويض | ع |
| `n` | ن |
| `π` | ط |
| `lim` | نها |
| الأرقام `0–9` | ٠–٩ |

كما تحول الفاصلة الرياضية إلى `،`، وسهم الاقتراب في النهاية إلى الشكل المناسب للقراءة العربية، مع الإبقاء على الرموز العالمية التي لا تحتاج ترجمة مثل `∞` و`∫` و`√` وعلامات العلاقات.

## ما يدعمه المحرك
- الكسور المتراكبة.
- الأسس والرموز العليا.
- الرموز السفلية والعليا معًا، مثل تقييم الدالة الأصلية بين حدين.
- الجذور.
- النهايات وشرط الاقتراب.
- التكامل المحدد وغير المحدد.
- التفاضلات: دس، دص، دع، دل.
- الدوال المثلثية واللوغاريتمية والأسية.
- الأقواس والفترات والإحداثيات والقوائم المفصولة بفاصلة عربية.
- العلاقات: =، ≠، ≤، ≥، <، >، ∈.
- الأعداد العربية الهندية داخل الصيغة وواجهة المحاكاة.

## قواعد الاتجاه
1. صفحة المحاكاة عربية `dir="rtl"` و`lang="ar"`.
2. كل عنصر `<math>` يحمل `dir="rtl"` صراحة، ولا يعتمد فقط على اتجاه العنصر الأب.
3. كل صيغة معزولة باستخدام `unicode-bidi: isolate` حتى لا تتداخل مع علامات الترقيم المحيطة.
4. لا تستخدم `font-mono` للصيغة النهائية.
5. تستخدم الصيغة خطوط رياضيات النظام أولًا (`STIX Two Math`, `Cambria Math`, `Noto Sans Math`) مع خطوط عربية للنصوص الرياضية (`Noto Naskh Arabic`, `Noto Sans Arabic`) كبدائل نظامية، دون شحن ملفات خطوط إضافية.

## بوابة الجودة
`client/src/exams/arabic-math.test.ts` يفحص:
- التحويل إلى الرموز والأرقام العربية.
- وجود MathML بنيوي للكسر والأس والجذر والنهاية والتكامل.
- وجود `dir="rtl"` على الصيغة.
- **كل مقطع رياضي في الأسئلة الخمسين وخياراتها وشروحها**؛ أي مقطع لا يستهلكه المحلل بالكامل يفشل CI.

## طبقة التوافق مع الواجهة الحالية
`ArabicExamTypography` يراقب صفحة المحاكاة فقط، ويحوّل المقاطع الرياضية القديمة بعد إنشائها إلى MathML. لا يغير بيانات الامتحان، ولا يعمل خارج مسار `#exam-pilot`. كما يحول الأرقام الظاهرة في واجهة المحاكاة إلى الأرقام العربية الهندية.

## مصادر القرار
- W3C Arabic mathematical notation: https://www.w3.org/TR/arabic-math/
- MDN MathML `dir`: https://developer.mozilla.org/en-US/docs/Web/MathML/Reference/Global_attributes/dir
- W3C MathML directionality: https://w3c.github.io/mathml-core/#directionality
- أرشيف نماذج الشهادة الثانوية اليمنية: https://meoh.gov.ye/services/high-school-exam-forms/

## حدود متعمدة
- لا تتحول البيانات المخزنة إلى رموز عربية؛ التحويل عرضي فقط.
- لا تستخدم صورًا للنص الرياضي، حتى يبقى قابلاً للتكبير والوصول والنسخ.
- لا يعتمد الاختبار على اتصال خارجي لتحميل محرك رياضيات أثناء الحل.
